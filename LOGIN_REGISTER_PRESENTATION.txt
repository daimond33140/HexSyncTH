1. ภาพรวมระบบ (System Overview)
--------------------------------------------------------------------------------
ระบบเข้าสู่ระบบและสมัครสมาชิกของเว็บไซต์ ถูกออกแบบตามมาตรฐานความปลอดภัยระดับสูง
ทำงานร่วมกันระหว่างฝั่งหน้าเว็บ (Frontend - React + TypeScript) และฝั่งเซิร์ฟเวอร์
(Backend - Express.js + Sequelize ORM + SQLite/PostgreSQL) 
โดยใช้สถาปัตยกรรมแบบ Token-Based Authentication (JSON Web Token: JWT) 
ร่วมกับการเข้ารหัสแบบทางเดียว (One-Way Cryptographic Hashing) ด้วย Bcrypt
และมีระบบตรวจจับการโจมตีแบบเรียลไทม์ (WAF & Anti-Brute Force Protection)


2. รายการไฟล์และหน้าที่ของแต่ละไฟล์ (File Structure & Components)
--------------------------------------------------------------------------------
[ ฝั่งหน้าเว็บ / Frontend ]
- src/App.tsx
  • ส่วนแสดงผลหน้าต่าง Pop-up (Auth Modal) รองรับ 3 แท็บ: เข้าสู่ระบบ, สมัครสมาชิก, ลืมรหัสผ่าน
  • ฟังก์ชัน handleLogin(): จัดการส่งคำขอเข้าสู่ระบบ, เช็คพิกัด GPS, จัดการ Token
  • ฟังก์ชัน handleRegister(): ตรวจสอบความถูกต้องของรหัสผ่าน ยืนยันรหัสผ่าน และส่งข้อมูลสมัคร

- src/deviceInfo.ts
  • ตรวจจับและดึงข้อมูลประจำเครื่อง (Device Fingerprint) เช่น เลขประจำเครื่องเฉพาะ (UDID),
    รุ่นอุปกรณ์ (Model), ระบบปฏิบัติการ (OS), และขนาดหน้าจอ เพื่อผูกกับประวัติผู้ใช้

[ ฝั่งหลังบ้าน / Backend ]
- server/routes/auth.js
  • จุดศูนย์รวม API การตรวจสอบตัวตนทั้งหมด (Register, Login, Check-Status, OTP Reset)
- server/models/User.js
  • โครงสร้างตารางฐานข้อมูลผู้ใช้ (username, email, passwordHash, creditBalance, role,
    registerIp, lastIp, deviceFingerprint, isBanned, ฯลฯ)
- server/middleware/wafSecurity.js
  • ระบบตรวจจับและป้องกันการสุ่มรหัสผ่าน (Anti-Brute Force / Credential Stuffing)
- server/middleware/ipBan.js
  • ระบบตรวจจับ Client IP และคัดกรอง IP ที่ถูกระงับสิทธิ์เข้าใช้งาน
- server/utils/geoIp.js
  • ถอดรหัสพิกัด Geolocation จาก IP (เมือง, จังหวัด, ประเทศ, ผู้ให้บริการเครือข่าย ISP)


3. หลักการทำงาน: ระบบสมัครสมาชิก (Register Workflow)
--------------------------------------------------------------------------------
ขั้นตอนที่ 1: การป้อนข้อมูล
  - ผู้ใช้กรอกข้อมูล: ชื่อผู้ใช้ (Username), อีเมล (Email), รหัสผ่าน (Password)
    และยืนยันรหัสผ่าน (Confirm Password)

ขั้นตอนที่ 2: การตรวจสอบขั้นต้นที่หน้าบ้าน (Frontend Validation)
  - ฟังก์ชัน handleRegister() ตรวจสอบว่ากรอกครบทุกช่องหรือไม่
  - ตรวจสอบว่ารหัสผ่านและยืนยันรหัสผ่านตรงกันทุกตัวอักษร
  - ดึงข้อมูลอัตลักษณ์เครื่อง (Device ID และ Device Model) เตรียมส่งให้เซิร์ฟเวอร์

ขั้นตอนที่ 3: ส่งข้อมูลไปยังเซิร์ฟเวอร์
  - ยิง HTTP POST ไปที่ Endpoint: /api/auth/register

ขั้นตอนที่ 4: การตรวจสอบและบันทึกที่เซิร์ฟเวอร์ (Server Validation & Storage)
  - ตรวจสอบในฐานข้อมูลว่า Username หรือ Email มีผู้อื่นใช้งานแล้วหรือไม่
    (หากซ้ำ จะตอบกลับ HTTP 409 Conflict)
  - นำรหัสผ่านไปผ่านฟังก์ชัน bcrypt.hash() จำนวน 10 รอบ (Salt 10 Rounds)
    ทำให้รหัสผ่านถูกแปลงเป็นชุดอักขระที่ไม่สามารถถอดรหัสย้อนกลับได้
  - ดึงหมายเลข IP ปัจจุบันของผู้ใช้ (Client IP)
  - บันทึกแถวข้อมูลใหม่ลงตาราง User ในฐานข้อมูล:
    * ยศเริ่มต้น: member
    * ยอดเงินเริ่มต้น: 0 บาท
    * บันทึก IP ที่สมัคร (registerIp) และเลขอุปกรณ์ (deviceFingerprint)
  - บันทึกลงตาราง Log กิจกรรมของระบบ (USER_REGISTER)

ขั้นตอนที่ 5: ออกตั๋วสิทธิ์ (JWT Token Generation)
  - เซิร์ฟเวอร์สร้าง JSON Web Token (JWT) ที่บรรจุ User ID, Username, Role
    และมีอายุใช้งาน 7 วัน
  - ตอบกลับ HTTP 201 พร้อม Token และข้อมูลผู้ใช้
  - เบราว์เซอร์บันทึก Token ลง localStorage ('hexsync_token') เพื่อคงสถานะล็อกอินอัตโนมัติ


4. หลักการทำงาน: ระบบเข้าสู่ระบบ (Login Workflow)
--------------------------------------------------------------------------------
ขั้นตอนที่ 1: ส่งคำขอเข้าสู่ระบบ
  - ผู้ใช้กรอก Username (หรือ Email) และ Password
  - หน้าบ้านขอพิกัด Browser GPS (หากผู้ใช้อนุญาต) และดึง Device Info
  - ยิง HTTP POST ไปที่ Endpoint: /api/auth/login

ขั้นตอนที่ 2: ด่านคัดกรองความปลอดภัย (WAF / Brute-Force Shield)
  - เซิร์ฟเวอร์นำ Client IP ไปตรวจสอบใน wafSecurity.js
  - หาก IP นี้เคยใส่รหัสผิดติดต่อกันเกิน 6 ครั้ง จะถูกบล็อกชั่วคราว (Lockout 15 นาที)
    และส่งรหัส HTTP 429 ทันที ป้องกันบอทโจมตีสุ่มรหัสผ่าน

ขั้นตอนที่ 3: ตรวจสอบบัญชีผู้ใช้และรหัสผ่าน
  - ค้นหาบัญชีจากฐานข้อมูลด้วย Username หรือ Email
  - หากไม่พบบัญชี หรือพบแต่รหัสผ่านผิด:
    * เพิ่มตัวนับ Failed Login ของ IP นั้น (+1)
    * หากตรวจพบการสุ่มรหัสผ่านข้ามบัญชีหลายชื่อ (Credential Stuffing / Hydra Attack)
      ระบบจะสั่งแบน IP ถาวรอัตโนมัติ
    * ตอบกลับ HTTP 401 แจ้งเตือนจำนวนครั้งที่ยังใส่ผิดได้
  - หากรหัสผ่านถูกต้อง (bcrypt.compare() ตรงกัน):
    * ล้างตัวนับรหัสผ่านผิดของ IP นั้นให้กลับเป็น 0

ขั้นตอนที่ 4: ตรวจสอบสถานะการระงับสิทธิ์ (Ban Check)
  - ตรวจสอบฟิลด์ user.isBanned ในฐานข้อมูล
  - หากเป็น true (ถูกแบน):
    * ตอบกลับ HTTP 403 พร้อมเหตุผลการแบน วันที่ถูกแบน และผู้สั่งแบน
    * หน้าบ้านจะนำไปแสดงหน้าจอเตือนการระงับสิทธิ์ และไม่อนุญาตให้เข้าใช้งาน

ขั้นตอนที่ 5: อัปเดตข้อมูลการใช้งานล่าสุด (Audit & Telemetry)
  - อัปเดต IP ใช้งานล่าสุด (lastIp), วันเวลาใช้งาน (lastActive)
  - อัปเดตข้อมูลรุ่นเครื่อง และพิกัดตำแหน่งทางภูมิศาสตร์ (City, Region, Country, ISP)
  - บันทึกประวัติการเข้าสู่ระบบลงใน Audit Log ของแอดมิน (USER_LOGIN)

ขั้นตอนที่ 6: สร้าง Session และเข้าสู่ระบบสำเร็จ
  - เซิร์ฟเวอร์ลงลายมือชื่อดิจิทัลออก JWT Token
  - หน้าบ้านบันทึก Token และข้อมูล User ลงใน localStorage
  - ปรับปรุง State ให้แสดงชื่อผู้ใช้, ยศ (Role), และยอดเงินคงเหลือบนหน้าเว็บทันที


5. จุดเด่นด้านความปลอดภัยสำหรับการนำเสนอ (Key Security Highlights)
--------------------------------------------------------------------------------
1. การเข้ารหัสระดับอุตสาหกรรม (Industry-Standard Password Hashing)
   - ใช้ Bcrypt Salted Hash 10 Rounds รหัสผ่านจะไม่ถูกบันทึกเป็นข้อความธรรมดา (Plain text)
     แม้ฐานข้อมูลจะถูกโจรกรรม ข้อมูลรหัสผ่านก็ไม่สามารถแกะกลับมาได้

2. ระบบป้องกันการเดารหัสผ่านอัจฉริยะ (Adaptive Anti-Brute Force Protection)
   - ตรวจจับความถี่การใส่รหัสผิดแยกตาม IP
   - มีระบบ Lockout หน่วงเวลา 15 นาที เมื่อใส่ผิดเกิน 6 ครั้ง
   - ตรวจจับการโจมตีแบบกระจาย (Credential Stuffing) และสั่งแบน IP อัตโนมัติ

3. สถาปัตยกรรมไร้สถานะ (Stateless JWT Authentication)
   - ไม่เปลืองหน่วยความจำ Memory บนเซิร์ฟเวอร์ในการเก็บ Session
   - มีการตรวจสอบสิทธิ์ (RBAC: Role-Based Access Control) แยกยศ Member, Admin, SuperAdmin

4. ระบบบันทึกอัตลักษณ์อุปกรณ์และพิกัด (Hardware & Geo-Location Tracking)
   - บันทึกเลขเครื่อง (UDID) เพื่อป้องกันการใช้เครื่องเดิมสร้างไอดีปั๊มยอดเงิน
   - สามารถระบุตำแหน่งของบัญชีผู้ใช้ลงบน Google Maps ให้แอดมินตรวจสอบได้แบบเรียลไทม์

5. ระบบตรวจสอบการแบนบัญชีแบบเรียลไทม์ (Real-Time Account Verification)
   - มี Polling ตรวจสอบสถานะการแบนกับเซิร์ฟเวอร์อย่างต่อเนื่อง
   - หากแอดมินสั่งระงับบัญชี ระบบจะตัดสิทธิ์และล็อกเอาต์ออกจากหน้าร้านค้าทันที

6. ประตูคัดกรองความปลอดภัย HexSyncTH Security MAX (Entrance Verification Gateway)
   - แสดงป๊อปอัปยืนยันความปลอดภัยทุกครั้งที่รีเฟรชหน้าเว็บ และต้องกดยอมรับก่อน Login
   - ระบบตรวจจับและปิดกั้นการเปิด Developer Tools / Inspect ทั้งแบบคีย์ลัดและผ่านเมนูเบราว์เซอร์
   - ป้องกันการดัดแปลงโค้ดฝั่ง Client (Anti-Tamper) และเข้ารหัสความปลอดภัยระดับสูงสุด
